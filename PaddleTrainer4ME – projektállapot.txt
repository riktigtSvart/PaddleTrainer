Munkastílus: egy módosítás → egy teszt → eredmény értelmezése → következő lépés. Ne találjunk ki jelenlegi kódot; ha bizonytalan, kérjünk friss fájlt.
1. Termékvízió
A PaddleTrainer4ME nem egyszerű edzésnaptár, hanem hosszú távú, adaptív sportolói edzéstervező/coach rendszer.
Fő sportok jelenleg:
- kajak
- futás
- úszás
- erőnlét
- később egyéb sportok
Tervezési hierarchia:
olimpiai / szezon cél
→ szezon / periódus / blokk
→ 3–6 hetes mezociklus
→ hét
→ edzés
→ tényleges eredmény
→ recovery / performance
→ jövőbeli terv módosítása

Fontos elv:
LOAD DEFICIT != AUTOMATIC LOAD INCREASE

Ha valaki kevesebbet teljesít a tervnél, nem szabad automatikusan „visszapótolni” a terhelést. Lehet fáradtság, betegség, stressz, utazás, iskola, rossz alvás stb.
A rendszerben külön kell kezelni:
Training Load State
Capacity
Readiness
Long-term Background

Továbbá:
acute != fatigue
chronic != fitness

A hosszú távú cél egy személyre szabott, tanuló rendszer:
GENERAL MODEL
+ ATHLETE HISTORY
+ CURRENT STATE
→ PERSONALIZED RESPONSE MODEL
→ TRAINING RECOMMENDATION
→ ACTUAL RESULT
→ MODEL UPDATE

Az ML-nek bizonytalanságot/confidence-ot is kezelnie kell, nem hamis pontosságot.

4. Polar session / target rendszer
Működik:
- training session import
- training target calendar
- structured workout parser
- phase / repeat parser
- exact Polar target ID matching
- reconciliation
- combined sync
Endpoint:
POST /api/v1/integrations/polar/sync?days=35

90 napos session import is tesztelve volt.
Fontos ismert anomáliák:
- Polar target reschedule/edit semantics miatt egy target ID dátuma eltérhet az actual session dátumától.
- Egy target neve és tényleges raw/parsed distance eltérhet.
- Completed target nem jelenti automatikusan, hogy actual session linkelt.
- Lehetnek spontaneous / unplanned actual sessionök.
Ezeket nem szabad csendben „javítani”.

21. Fontos későbbi irányok
Még nincs megépítve, de terv:
Capability / availability semantics
Ne legyen minden hiány egyszerűen null.
Később megkülönböztetendő:
AVAILABLE
NO_DATA
NOT_SUPPORTED
NOT_AUTHORIZED
NOT_SYNCED
ERROR

ResponseMeasurement / physiological response
Az edzés utáni objektív recovery később pl.:
heart_rate_end
heart_rate_60s
heart_rate_120s
hrr_60
hrr_120

de ezeket providerfüggetlen measurementként akarjuk kezelni.
HRR
A 24/7 Polar HR önmagában valószínűleg nem elég precíz HRR60/120 számításhoz.
Ideális esetben az edzés recordingban hagyunk 2–3 perc standardizált recovery szakaszt.
ML
Ne egyetlen fatigue score legyen a tanítójel.
Inkább:
load
→ objective response trajectory
→ subjective response trajectory
→ next-day readiness
→ future performance

22. Munkamódszer
Fontos a folytatásnál:
- magyarul dolgozunk;
- pontos path + pontos kód;
- egyszerre egy változtatás;
- utána teszt;
- csak a teszt után következő lépés;
